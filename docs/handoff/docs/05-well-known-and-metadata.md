# 05 — Metadata, well-known files, and the agent stack

Everything here ships in `astro/public/` and is copied verbatim to `dist/`. Each file: what it is, the spec it follows, what to edit, how to test.

## 1. `robots.txt` — RFC 9309 (access policy; "layer 1")

```
User-agent: *
Allow: /
Allow: /agents.txt
Allow: /agents.json
Allow: /llms.txt
Sitemap: https://akl.dev/sitemap-index.xml
```
Everything public is crawlable. The explicit `Allow` lines exist because the agents.txt spec (§4.3) requires that `/agents.txt` be reachable at its canonical path; they're redundant under `Allow: /` but make the intent legible. If the owner later wants to opt out of training crawlers, add `User-agent: GPTBot` / `CCBot` / `Google-Extended` blocks — a policy choice, not made here.
Test: `curl -s https://akl.dev/robots.txt`.

## 2. `sitemap-index.xml` + `sitemap-0.xml` — generated by `@astrojs/sitemap` ("layer 2")

Generated at build from `site` in `astro.config.mjs`. Linked from `<link rel="sitemap">` and `robots.txt`. Nothing to edit; new pages appear automatically.
Test: `curl -s https://akl.dev/sitemap-index.xml` lists `sitemap-0.xml`, which lists `https://akl.dev/`.

## 3. `humans.txt` — humanstxt.org

Free-form, sectioned (`/* TEAM */`, `/* SITE */`). Update when the stack changes. Purely for people who look.

## 4. `llms.txt` — llmstxt.org ("layer 3", content briefing)

Structure (in order, per spec): H1 site name (required) → blockquote summary → free body paragraph(s) → H2 sections of `- [name](url): note` links → optional **`## Optional`** section that agents may skip. Ours lists the markdown twin of the page, the elsewhere links, and the agent/humans files under Optional.

**Markdown twin:** `public/index.html.md` is the page as clean markdown at the spec's conventional URL (`/index.html.md`). The page's `<head>` has `<link rel="alternate" type="text/markdown" href="/index.html.md">` and `<link rel="describedby" href="/llms.txt">`; `_headers` also sends `Link: </llms.txt>; rel="describedby"` so non-HTML fetchers discover it. **Keep `index.html.md` in sync with the page copy** — `verify.mjs` does not diff them (add a check if copy changes often). When `/notes` exists, add `## Notes` with one line per post and consider `llms-full.txt` (everything concatenated).

## 5. `agents.txt` + `agents.json` — agents-txt.com v1.0 ("layer 4", capability discovery)

The site advertises **no** capabilities. The files exist so an agent gets a definitive answer in one request. `agents.txt` is comments only (every directive block is optional); `agents.json` carries `$schema`, `version: "1.0"`, `standard`, and `site{name,url,description}` plus a `docs` pointer (unknown fields are ignored by parsers per spec). When something real appears — e.g. an MCP endpoint on 16384.dev — add `MCP: https://…` to the `.txt` **and** an `mcp: [{url,type,description}]` block to the `.json`; the two must agree.

## 7. In-page metadata (`Base.astro`)

- `<title>Adam Loghry</title>`; `meta description`; `<link rel="canonical">` (absolute, per page).
- `color-scheme: light dark`; two `theme-color` metas with media queries.
- Open Graph: title, description, type, url, image (`/og.png`, 1200×630, regenerated by `npm run og`), image width/height; `twitter:card summary_large_image`.
- Icons: `favicon.svg` (adapts to dark via `prefers-color-scheme` inside the SVG), `apple-touch-icon.png` 180×180, `site.webmanifest`.
- `rel="me"` ×3 in head (Mastodon, Bluesky, GitHub) — plus on the in-body links.
- JSON-LD `Person` (schema.org): name with middle initial, `givenName`/`familyName`, `jobTitle`, `worksFor` Google, Seattle address, `sameAs` list. Test with Google's Rich Results test or `https://validator.schema.org/`.

## 8. `_headers` (Cloudflare Pages)

Security headers on `/*`: `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, a tight `Permissions-Policy`, and a CSP:
```
default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;
font-src 'self'; connect-src 'none'; frame-ancestors 'none'; base-uri 'self'; form-action 'none'
```
`'unsafe-inline'` for scripts covers the two inline scripts (theme-before-paint, JSON-LD — JSON-LD isn't executed, but some browsers still check it). To tighten: compute SHA-256 of the exact inline script text at build and emit `script-src 'self' 'sha256-…'`; Astro's `is:inline` output is byte-stable, so a tiny post-build step can do it. Style `'unsafe-inline'` is needed because the generator sets per-element `style=""` — switch to `style-src-attr 'unsafe-inline'` + `style-src 'self'` for a narrower grant.
Caching: `/_astro/*` immutable one year (hashed filenames); `og.png` one day; `.well-known/*` one hour.
Test: `curl -I https://akl.dev/` and check headers; `https://securityheaders.com`.

## 9. Things deliberately **not** added

- No analytics script (no beacon, no cookies, no consent banner needed). If wanted: Cloudflare Web Analytics is cookieless; update CSP.
- No `<meta name="robots">` — defaults are right.
- No `hreflang` — single language.
- No RSS yet — comes with `/notes` (`@astrojs/rss`), and then `llms.txt` gets a `## Notes` section.
